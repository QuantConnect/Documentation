Restarts don't save the state of your algorithm. When you stop and redeploy an algorithm, update it, or an automatic restart recovers it from a runtime error, LEAN starts a new instance of the algorithm and runs its Initializeinitialize method again. Class members, indicators, rolling windows, universe selections, and pending scheduled events all start empty.

The following table shows the state that a restart recovers:

State Source
Cash Your brokerage account. QuantConnect Paper Trading has no brokerage account, so the platform saves the last known cash and uses it to pre-fill the Algorithm Cash State section of the deployment wizard when you redeploy.
Holdings Your brokerage account. For QuantConnect Paper Trading, the platform saves the last known holdings and uses them to pre-fill the Algorithm Holdings State section of the deployment wizard when you redeploy.
Open orders Your brokerage account, if the brokerage integration can fetch open orders. Otherwise, the algorithm restarts without them. QuantConnect Paper Trading doesn't restore open orders.
Everything else Nothing. The algorithm rebuilds it.

To rebuild indicators and other data-driven state, warm up the algorithm. To recover state that history can't rebuild, like entry prices, trade counters, or the current step of a multi-step strategy, save it in the Object Store while the algorithm runs and load it back in Initializeinitialize. To check that the algorithm recovers, restart it while paper trading.
