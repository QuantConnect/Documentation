The static OS class in the QuantConnect namespace exposes memory and CPU metrics that you can read from your algorithm to monitor resource usage during backtests and live trading.

The following table lists the static members of the OS class that report memory and CPU usage:

Member Data Type Description
ApplicationMemoryUsedAPPLICATION_MEMORY_USED longint Private memory allocated to the current process, including managed and unmanaged memory, in megabytes.
TotalPhysicalMemoryUsedTOTAL_PHYSICAL_MEMORY_USED longint Managed-runtime RAM usage (sampled with GC.GetTotalMemorygc.get_total_memory), in megabytes. LEAN's memory monitor samples this value.
CpuUsageCPU_USAGE decimalfloat Total CPU usage as a percentage, sampled on a background thread.
GetServerStatistics()get_server_statistics() Dictionary<string, string>Dictionary[str, str] Snapshot dictionary with CPU Usage, Used RAM, Total RAM, Hostname, and LEAN Version entries.

The following examples show how to read these metrics from an algorithm:

// Log the current memory usage of the algorithm process.
Log($"Total physical memory used: {OS.TotalPhysicalMemoryUsed} MB");
Log($"Application memory used: {OS.ApplicationMemoryUsed} MB");

// Log the current CPU usage as a percentage.
Log($"CPU usage: {OS.CpuUsage}%");

// Log a full snapshot of the server statistics.
foreach (var kvp in OS.GetServerStatistics()) Log($"{kvp.Key}: {kvp.Value}");
# Log the current memory usage of the algorithm process.
self.log(f"Total physical memory used: {OS.TOTAL_PHYSICAL_MEMORY_USED} MB")
self.log(f"Application memory used: {OS.APPLICATION_MEMORY_USED} MB")

# Log the current CPU usage as a percentage.
self.log(f"CPU usage: {OS.CPU_USAGE}%")

# Log a full snapshot of the server statistics.
for kvp in OS.get_server_statistics():
    self.log(f"{kvp.key}: {kvp.value}")

LEAN monitors the process's RAM usage during backtests and live trading so it can stop the algorithm gracefully when it approaches the node's memory limit, instead of letting the runtime crash. To avoid killing an algorithm over a short-lived spike, LEAN does not act on the raw reading — it smooths the sampled value first and checks the smoothed value against the limit.

LEAN samples OS.TotalPhysicalMemoryUsedOS.TOTAL_PHYSICAL_MEMORY_USED once per second in backtests and once every 10 seconds in live trading, and feeds each sample into an exponential moving average. The engine sets emaPeriod = 60, so the smoothed reading covers roughly the last minute of a backtest and the last 10 minutes of a live deployment. 

// Update the smoothed memory reading on each sample.
sample = OS.TotalPhysicalMemoryUsed;
memoryUsed = Convert.ToInt64((emaPeriod-1)/emaPeriod * memoryUsed + (1/emaPeriod)*sample);
# Update the smoothed memory reading on each sample.
sample = OS.TOTAL_PHYSICAL_MEMORY_USED
memory_used = int((ema_period - 1) / ema_period * memory_used + (1 / ema_period) * sample)

LEAN stops the algorithm when either of the following conditions is true:

  • The smoothed reading exceeds the node's memory limit.
  • A single raw sample exceeds twice the node's memory limit.

The second condition is what makes short-lived spikes survivable. A universe selection pass, an Option chain, or a bulk history request can allocate well above the limit for a few samples without stopping the algorithm, as long as it releases the memory before it lifts the smoothed reading above the limit. An algorithm on a 512MB node can therefore touch just under 1GB on a single sample, but it has to average below 512MB.

Once a minute, if the smoothed reading is above 80% of the limit, LEAN writes Execution Security Error: Memory usage over 80% capacity. Sampled at {lastSample} to the log. Treat 80% of the limit as the level to design for, which is 410MB on a 512MB node. An algorithm that sits above it has no room left for the spikes the allowance exists to cover.

When LEAN stops the algorithm, it reports the runtime message Execution Security Error: Memory Usage Maxed Out - {memoryCap}MB max, with last sample of {lastSample}MB., where {memoryCap} is the node's configured limit and {lastSample} is the most recent reading.
