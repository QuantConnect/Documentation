There are no request quotas on the QuantConnect API, but the remote MCP server is limited by your agent nodes and the client you use may have quotas. For more information about the client quotas, see the Quotas section for one of the supported MCP clients.

Agent Node Sessions

The remote MCP server runs your tool calls in a session on one of your agent nodes. The following rules apply to these sessions:

  • Each session occupies one agent node for as long as it runs.
  • Sessions are per project. The first tool call for a project starts a session for that project, and later calls for the same project reuse it.
  • The list_projects, read_project, and create_project tools don't use a session, so they work even when all your agent nodes are in use.
  • Mia chats, agent tasks, and MCP sessions all use the same agent nodes. While an MCP session holds a node, a Mia message or an agent task can't use that node, and while a Mia chat or an agent task holds a node, an MCP call can't start a session on it. A Mia chat or an agent task can hold a node for several hours while it works.
  • A session can take more than 60 seconds to start. Until it's ready, tool calls for the project return an error that asks you to retry.

To run MCP calls and Mia chats or agent tasks at the same time, or to work on several projects at once, add agent nodes. To see which project holds each node and to free a node, open the Resources page.
