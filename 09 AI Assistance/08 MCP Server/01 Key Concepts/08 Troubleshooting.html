The following sections explain some issues you may encounter and how to resolve them.

Service Outages

The MCP server relies on the QuantConnect API and the client application. To check the status of the QuantConnect API, see our Status page. To check the status of your client and the LLM, see their status page.

Missing Agent Node

If your organization only has the free A-MICRO agent node, the MCP server returns the following error message:

The QuantConnect Remote MCP Server requires a dedicated Assistant node (A1-1, A4-12, A16-32). Purchase nodes on the pricing page.

To resolve this issue, add a paid agent node to your organization.

Agent Nodes in Use

If a tool call needs to start a session for a project and all your agent nodes are in use, the MCP server returns the following error message:

All your Assistant nodes are currently in use. Stop a running assistant to free one up, or purchase more nodes in the pricing page.

The node can be held by an MCP session for another project, a Mia chat, or an agent task, and retrying the call doesn't help until that session ends. To resolve this issue, finish working with one project before you move to the next, wait for the Mia chat or agent task to finish, or stop the node. For more information about how sessions share agent nodes, see Quotas.

Server Still Starting

If the session for a project takes more than 60 seconds to start, the MCP server returns the following error message:

The project's MCP server is still starting, retry the call in a few seconds

To resolve this issue, retry the call. The session keeps starting in the background, and once it's ready, the call succeeds.
